Mono-repo Architecture

Structuring the project for multi-platform growth (Web + WeChat).

Proposed File Structure

apps/
web/ (Existing Vite App)
miniprogram/ (New Taro App)
packages/
shared/ (Supabase Client, Types, Utils)
ui/ (Tailwind Config, Common Design Tokens)

The "Brain" (Shared Logic)

All your current hard work on **Supabase RPCs, Auth state, and Booking logic** will move to packages/shared. Both the Web and Mini Program will use the exact same code for these features.

Mini Program "Body"

The Mini Program will have its own UI components using Taro's <View> and <Text>, but it will behave identically to the Web app because they share the same backend logic.

No AppID? No Problem.

We will use the WeChat DevTools "Test Mode". It allows us to build and simulate the entire Mini Program experience using a temporary "Guest" ID. You only need the official AppID when you're ready to submit to the App Store.
