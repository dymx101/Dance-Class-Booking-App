Design Section 1: Atomic Booking Functions

Server-side logic for data integrity and business rules.

1. book_class()

-- Atomic Steps:

  1. Check if user has > 0 passes.
  2. Check if instance is NOT full.
  3. Deduct 1 pass from users.
  4. Insert record into bookings.
  5. Return 'success' or specific 'error_code'.

Prevents race conditions where two users book the last spot at the exact same millisecond.

2. cancel_booking()

-- Strict Rules:

  1. Verify booking belongs to user.
  2. Check class_instances.start_time.
  3. IF > 1 hour away:
       - Delete booking.
       - Add 1 pass back to user.
  4. ELSE:
       - Mark booking as 'no_show'.
       - KEEP user's pass.

Enforces the studio policy of "No refunds for late cancellations."

The "Successor" Trigger

When a booking is deleted (cancelled on time), a trigger automatically finds the user with the lowest queue_number in the waitlist for that class and calls book_class() for them.
