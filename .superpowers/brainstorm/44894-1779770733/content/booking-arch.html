Booking Architecture

Designing a robust system for atomic transactions and automatic waitlists.

1. Atomic Database RPC (SQL)

Recommended

We create a book_class() Postgres function. It executes the entire booking (Check Passes → Check Capacity → Insert Booking → Deduct Pass) in one single atomic transaction.

✓ Zero Race Conditions (No double-booking)
✓ Maximum Performance
✓ Perfect Data Integrity
✗ Harder to debug than JS

2. Supabase Edge Functions (TS)

A TypeScript function handles the booking. It uses the Supabase service role to perform multiple queries.

✓ Easy to write (TypeScript)
✓ Great for 3rd-party integrations
✗ Slower (Multiple DB roundtrips)
✗ Risk of race conditions if not careful
