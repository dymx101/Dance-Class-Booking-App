Design Section 1: In-App Realtime Architecture

Instant feedback and synchronization via Supabase Realtime.

New `notifications` Table

  • id (UUID) - Primary Key
  • userId (UUID) - Recipient (FK to users)
  • type (TEXT) - e.g. 'waitlist_promoted', 'purchase'
  • title (TEXT) - Short header
  • message (TEXT) - Notification body
  • isRead (BOOL) - Default: false

A Postgres trigger will automatically insert a row into this table whenever a user is promoted from the waitlist or a booking is confirmed.

Broadcasting Logic

// Supabase Realtime Flow:

  1. App subscribes to notifications channel on mount.
  2. Database change occurs (Insert).
  3. Realtime broadcast pushes new row to Client.
  4. Frontend displays a "Live Toast" and updates the "Unread Count" badge.

We will also use Realtime to sync the **global schedule** (bookedCount), so users see spots disappear live without refreshing.
