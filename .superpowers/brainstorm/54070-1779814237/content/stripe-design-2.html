Design Section 2: Webhook Fulfillment

Reliably delivering passes after successful payment.

stripe-webhook Edge Function

// Critical Security Steps:

  1. Verify Stripe-Signature header.
  2. Listen for checkout.session.completed.
  3. Extract metadata (userId, cardId).
  4. Database Fulfillment (Atomic):
       - Update users.remainingPasses.
       - Insert purchase_records.
  5. Return 200 OK to Stripe.

Webhooks ensure users get their passes even if they close their browser tab before the redirect completes.

Integrity Measures

  • Idempotency We will use the Stripe payment_intent_id as a unique constraint to prevent adding passes twice for the same payment.
  • Service Role Access The Edge Function uses the Supabase service_role key to bypass RLS, ensuring fulfillment is guaranteed.
  • Error Handling If fulfillment fails (e.g. DB down), we return a 5xx error. Stripe will automatically retry the webhook until it succeeds.
